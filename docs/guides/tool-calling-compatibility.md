# Tool Calling 호환성을 판단하는 방법

이 문서는 모델 서버에서 Tool Calling을 사용할 수 있는지 판단할 때 무엇을 확인해야
하는지 설명합니다. 이어서 OpenAI Python SDK와 OpenAI 호환 Chat Completions API로 실제
호환성을 검증하는 방법을 다룹니다.

## Tool Calling 지원은 무엇으로 결정되는가

Tool Calling에서 모델은 도구를 직접 실행하지 않습니다. 모델은 사용할 도구와 인자를
구조화된 형태로 요청하고, 애플리케이션이 도구를 실행한 뒤 그 결과를 모델에 돌려줍니다.

이 흐름이 동작하려면 다음 요소가 함께 호환되어야 합니다.

| 요소 | 역할 |
| --- | --- |
| 모델 | 요청에 맞는 도구를 선택하고 인자를 생성합니다. |
| 채팅 템플릿 | 도구 정의와 도구 호출 기록을 모델이 이해할 입력으로 구성합니다. |
| 추론 서버 | 모델 출력을 해석해 구조화된 Tool Call 응답으로 변환합니다. |
| API와 SDK | 도구 정의, 호출 정보와 실행 결과를 같은 형식으로 주고받습니다. |

따라서 모델 설명에 Tool Calling 지원이 표시되어 있다는 사실만으로 실제 애플리케이션과의
호환성이 보장되지는 않습니다. 모델, 채팅 템플릿, 추론 서버와 API를 결합한 환경에서
확인해야 합니다.

## 문서와 설정에서 먼저 확인할 내용

먼저 모델과 추론 서버의 공식 문서에서 다음 내용을 확인합니다.

- 모델 또는 채팅 템플릿이 도구 정의와 Tool Call 메시지를 지원하는가
- 추론 서버가 Tool Calling을 활성화하는 방법을 제공하는가
- 사용할 API가 도구 정의를 받고 구조화된 Tool Call을 반환하는가

예를 들어 `llama-server`는 Jinja 채팅 템플릿을 사용해 OpenAI 형식의 Function Calling을
처리합니다. 모델의 템플릿이 적합하지 않으면 다른 템플릿을 지정할 수도 있습니다. 이는
[llama.cpp Function Calling 문서](https://github.com/ggml-org/llama.cpp/blob/master/docs/function-calling.md)에서
확인할 수 있습니다.

이 단계는 해당 조합이 동작할 가능성을 확인하는 과정입니다. 실제 호환성은 API 요청을
보내서 확인해야 합니다.

## OpenAI 호환 API로 직접 검증하기

먼저 이름과 인자가 명확한 함수 도구 하나를 `tools`에 정의하고 Chat Completions 요청을
보냅니다. `tool_choice`로 그 도구를 지정하면 모델의 선택 능력과 관계없이 요청·응답 형식의
호환성만 분리해서 확인할 수 있습니다.

응답에서는 다음 항목을 확인합니다.

- `tool_calls`에 예상한 함수 호출이 포함되어 있는가
- `tool_calls[].id`와 `function.name`이 존재하는가
- `function.arguments`가 유효한 JSON이며 정의한 스키마에 맞는가

그다음 도구 실행 결과를 `tool_call_id`로 원래 호출의 `id`와 연결해 대화 기록에 추가하고
다시 요청합니다. 모델이 결과를 바탕으로 후속 응답을 생성하면 Tool Call 요청부터 결과
전달까지의 왕복 흐름이 호환된다고 판단할 수 있습니다. 이 호출 ID의 연결 방식은
[OpenAI Function Calling 문서](https://developers.openai.com/api/docs/guides/function-calling)에
정의되어 있습니다.

강제한 도구 호출이 성공했다는 것은 API 형식이 호환된다는 의미입니다. 모델이 필요한
상황에서 스스로 올바른 도구를 선택하는지는 증명하지 않습니다. 자율적인 도구 선택 능력은
강제를 제거하고, 도구가 필요한 요청과 필요하지 않은 요청을 반복해서 평가해야 합니다.

모델, 채팅 템플릿, 추론 서버, 서버 설정 또는 SDK 연동 방식이 바뀌면 호환성도 다시
확인해야 합니다.
